# Tokn V0.1 - Measurement Architecture

Status: DESIGN READY
Date: 2026-09-27

## Goal

V0.1 makes Tokn resilient to incomplete Codex evidence.

The observer must answer four independent questions:

1. What model work actually happened?
2. What tools/workspaces were actually used?
3. Did the task finish successfully?
4. Is the evidence complete enough to support a conclusion?

A source adapter is never allowed to answer all four by assumption.
## New pipeline

Codex evidence sources
  -> source health assessment
  -> source-specific adapters
  -> normalized RunEvent IR
  -> session/thread graph
  -> tool/workspace graph
  -> token ledger
  -> terminal-status reducer
  -> policy evidence reducer
  -> experiment-validity reducer
  -> reports / SQLite

Primary difference from V0.0:
source health and coverage are evaluated BEFORE metrics are trusted.

## Evidence sources

L0 - Standard session rollout JSONL
- always discoverable in normal Codex Desktop use;
- contains token_usage_record;
- contains session_meta and subagent relationships;
- contains custom tool calls/outputs;
- contains task terminal errors.

L1 - Diagnostic Rollout Trace
- richer when complete;
- may expose direct inference/tool payload details;
- must pass a health gate;
- absence/incompleteness must trigger fallback, never zero metrics.

L2 - Reducer/oracle
- used to corroborate diagnostic bundles when available.

L3 - OS/process/project observations
- timing, process identity, filesystem snapshots, workspace outputs.
## Run identity

V0.1 introduces RunGroup.

RunGroup fields:
- experiment_run_id;
- root_session_id;
- parent_thread_id;
- member_thread_ids;
- source artifacts;
- started_at / ended_at;
- terminal_status;
- workspace roots;
- policy identity;
- runtime versions.

Subagent membership is derived from:
- session_meta.session_id;
- parent_thread_id;
- forked_from_id;
- source.subagent.thread_spawn;
- timestamps as secondary corroboration.

Token accounting is aggregated across every member thread exactly once.

## Terminal status

Every RunGroup must end in one of:
- COMPLETED;
- INCOMPLETE_USAGE_LIMIT;
- INCOMPLETE_CANCELLED;
- INCOMPLETE_ERROR;
- INCOMPLETE_USER_ABORT;
- UNKNOWN_TERMINAL_STATE.

A token report without terminal status is incomplete.

## Source health

Each source receives:
- status: HEALTHY / PARTIAL / EMPTY / MALFORMED / UNSUPPORTED;
- expected_surface;
- observed_surface;
- coverage ratio when meaningful;
- provenance.

Example:
diagnostic trace with 4 protocol events and zero inference/tools:
status = PARTIAL
not HEALTHY.
## Source selection rule

For each metric family, Tokn chooses evidence independently.

Example:
- token totals: session rollouts can be authoritative fallback;
- inference request payload bytes: diagnostic trace only;
- parent/subagent graph: session rollouts preferred;
- filesystem outputs: Tokn snapshot observer;
- task terminal status: session task_complete preferred.

Tokn must never replace UNKNOWN with zero because another source is absent.

## Reconciliation

If L0 and L1 both provide the same metric:
- compare values;
- preserve both provenance records;
- report agreement/conflict;
- select the configured authority only after comparison.

No silent preference.

## V0.1 acceptance

V0.1 measurement architecture is accepted when:
- Experiment 001 can be reprocessed from standard rollouts;
- parent + 3 subagents are grouped automatically;
- aggregate tokens equal 5,311,758 logical tokens;
- usage_limit_exceeded is recovered automatically;
- the 4-event diagnostic trace is marked PARTIAL;
- no zero-valued diagnostic report can override healthy session evidence.
