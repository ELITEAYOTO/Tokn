# Tokn V0.1 - Implementation Plan

Status: IN PROGRESS - P0-P5 DONE / P6 IN PROGRESS
Date: 2026-09-29

## Objective

Make Tokn trustworthy on real Codex Desktop runs before attempting another active token optimization experiment.

V0.1 is a measurement-hardening release.

No new RAG, embeddings, Tree-sitter, GUI or memory system is added in this phase.

## Definition of done

V0.1 is done only when Experiment 001 can be replayed automatically and Tokn reports:

- root session + 3 subagents grouped as one RunGroup;
- 80 usage records;
- logical total = 5,311,758;
- uncached input = 226,025;
- terminal status = INCOMPLETE_USAGE_LIMIT;
- diagnostic trace health = PARTIAL;
- policy result != PASS;
- B07-C_WORKING selected as candidate output;
- 13 added / 4 modified / 0 removed vs B07-B_FROZEN;
- verify:local executed against B07-C_WORKING\PROJECT;
- experiment verdict = INSTRUMENTATION_ONLY.

# Phase P6 - Policy placement and evidence

Status: IN PROGRESS

Implemented foundations:
- PolicyPlacement / SessionPolicyEvidence / PolicyEvidenceReport domain types;
- explicit enforcement states including UNAVAILABLE / SUPPORTED_UNVERIFIED / SUPPORTED_NOT_ACTIVE / ENFORCED / NOT_PROVEN;
- session scanner for policy markers in instruction fields;
- explicit repository policy-read detection from parsed tool calls.

Implemented in current P6 pass:
- aggregate evidence across the full RunGroup;
- expose text + JSON through `inspect-policy`;
- combine hint exposure, observed cap behavior and enforcement status without conflating them;
- connect Experiment 001 FINISH to the policy evidence report;
- real replay reproduces 58 targets / 17 violations and finds explicit policy-file reads in all 4 sessions;
- generic multi-placement lifecycle with per-path backup/hash/restore ;
- Experiment 001 places the hint at PROJECT and workspace watch root, then restores both conservatively ;
- START/FINISH/RECOVER keep legacy-run compatibility ;
- disabled-by-default PreToolUse handler prototype + privacy-first decision audit ;
- Codex hook mechanism confirmed supported, but cap-field visibility remains unverified.

Remaining target:
- capture one controlled real PreToolUse callback and freeze its actual schema ;
- prove whether the exec path exposes `max_output_tokens` to the hook ;
- validate nested Code Mode behavior with the real callback ;
- only then decide whether hard cap enforcement can be promoted beyond SUPPORTED_UNVERIFIED.

Priority: HIGH

Tasks:
1. Place policy_hint only on declared roots known before launch (source project + watch root).
2. Preserve/restore every touched AGENTS.md independently by exact installed hash.
3. Resolve the actual dynamic output workspace from session evidence after the run.
4. Record whether policy appears in session instruction evidence.
5. Record whether repository policy files were explicitly read.
6. Separate hint exposure from observed compliance.
7. Never label soft policy as enforced.
8. Validate the real PreToolUse payload before relying on any undocumented field.

Research subtask:
Codex has a supported PreToolUse hook for Bash/tool mediation.
Official docs guarantee `tool_input.command`, but do not currently guarantee Tokn's needed `max_output_tokens` field.
Capture one controlled callback before deciding whether hard cap enforcement is actually available.

Exit criterion:
